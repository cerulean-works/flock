# flock s3

S3 keys for your organizations' buckets, for the shell and the AWS tools, and the buckets themselves. The server must have [S3 storage](../../app/s3-behavior) turned on. Every command signs in as [How credentials are found](../credentials) describes, so `flock login` or `FLOCK_TOKEN` is all it needs.

## flock s3 credentials

Issues a new ephemeral S3 key and prints it.

```bash
flock s3 credentials [--org ORG] [--ttl DURATION] [--read-only] [--format env|json|process] [--host URL]
```

| Flag | Default | Meaning |
|---|---|---|
| `--org` | your default organization | The organization whose buckets the key covers. |
| `--ttl` | the organization's ephemeral lifetime (8 hours unless changed) | How long the key lives: seconds, or a number with `s`, `m`, `h` or `d`, such as `15m` or `2h`. More than the organization allows gets its limit. |
| `--read-only` | off | A key that can only read. |
| `--format` | `env` | What to print; see below. |
| `--host` | `FLOCK_HOST`, else your sign-in's | The Flock API to ask. |

| Format | Prints | For |
|---|---|---|
| `env` | `export AWS_ACCESS_KEY_ID=…` lines, with the endpoint and region | `eval "$(flock s3 credentials)"` in a shell or job script |
| `json` | the API's answer: `endpoint`, `region`, `org`, `access_key_id`, `secret_access_key`, `read_only`, `expires_at` | other programs |
| `process` | the AWS CLI's `credential_process` JSON, with `Version: 1` and `Expiration` | AWS profiles; see [`flock s3 configure`](#flock-s3-configure) |

```bash
eval "$(flock s3 credentials)"
aws s3 cp model.pt s3://checkpoints/run-1/model.pt
aws s3 ls s3://checkpoints/run-1/
```

The `env` format sets `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL`, `AWS_ENDPOINT_URL_S3`, `AWS_REGION` and `AWS_DEFAULT_REGION`. Each run makes a new key, which ends with your sign-in: `flock logout` revokes it.

## flock s3 configure

Adds an AWS profile that runs `flock s3 credentials --format process` whenever it needs a key, so the AWS CLI, boto3 and DuckDB's `credential_chain` get a new one each time the last expires, and none is stored on disk.

```bash
flock s3 configure [--org ORG] [--profile NAME] [--read-only] [--host URL]
```

| Flag | Default | Meaning |
|---|---|---|
| `--org` | your default organization | The organization whose buckets the profile reaches. |
| `--profile` | `flock` | The profile's name. `default` writes the `[default]` section. |
| `--read-only` | off | Only ever fetch keys that can only read. |
| `--host` | `FLOCK_HOST`, else your sign-in's | The Flock API to ask. |

It writes to `AWS_CONFIG_FILE`, else `~/.aws/config`, and asks before replacing a profile of the same name. Other profiles stay as they are. The profile pins the organization resolved by the setup command (shown as `ORGANIZATION_ID` below). It looks like this:

```text
[profile flock]
credential_process = /usr/local/bin/flock s3 credentials --org ORGANIZATION_ID --format process
endpoint_url = <endpoint returned by Flock>
region = us-east-1
s3 =
    addressing_style = path
```

```bash
aws s3 ls s3://checkpoints/ --profile flock
```

```python
import boto3

s3 = boto3.Session(profile_name="flock").client("s3")
```

> [!NOTE]
> The AWS tools ask for a new key once the current one has fewer than 15 minutes left, and refuse one with fewer than 10. Keep keys from `credential_process` longer than 15 minutes, as the default 8 hours is.

## flock s3 buckets

Lists, creates and deletes an organization's buckets. The proxy doesn't create or delete buckets, so this is where you do it (or on the organization's page).

```bash
flock s3 buckets list [--org ORG] [--json] [--host URL]
flock s3 buckets create [--org ORG] [--host URL] NAME...
flock s3 buckets delete [--org ORG] [--yes] [--host URL] NAME...
```

- **Names** use lowercase letters, digits, hyphens and dots, and start and end with a letter or digit. They can't be changed later.
- **Any member** can create buckets. Only organization admins can delete them.
- **`delete`** asks first, unless `--yes` is given. It returns once the bucket is gone from the organization; the server empties it in the background, and the name is free again after that.

```bash
flock s3 buckets create checkpoints shards
flock s3 buckets list
```

## Errors

Without a sign-in, when the server has no S3, or when the server refuses (an invalid name, a role that may not delete), a command exits with code `1` and prints the reason. An invalid flag exits with code `2`.

# S3 keys and buckets

Endpoints for S3 keys and organizations' buckets. Paths are relative to `/api/v1`. They all answer 404 with `{"error": "S3 isn't enabled on this server"}` when the server has no S3; [`GET /auth/config`](auth#auth-config) tells clients beforehand. For how the pieces fit, see [S3 storage](../s3).

## Ephemeral keys[[credentials]]

### `POST /s3/credentials`

Exchanges the request's credential for a new ephemeral key. Any credential works; the CLI sends its CLI token, and CI an API key. The body is optional:

| Field | Default | Meaning |
|---|---|---|
| `org` | your default organization | The organization whose buckets the key covers. One you don't belong to answers 404. |
| `ttl` | the organization's ephemeral lifetime | Seconds the key lives. More than the ephemeral lifetime gets the lifetime. |
| `read_only` | `false` | A key that can only read. |

```json
{"endpoint": "https://s3.flock.example.com", "region": "us-east-1", "org": "acme", "access_key_id": "FLKD2J5W7QK3MZ4XA6TB", "secret_access_key": "1QtX…", "read_only": false, "expires_at": 1793134800.5}
```

Each call makes a new key, named after the machine (`gpu-node-7 (ephemeral)`) or the API key. It ends with the CLI sign-in or API key that asked for it.

## Your keys[[keys]]

A key is listed as:

| Field | Meaning |
|---|---|
| `id` | Its integer id, for revoking it. |
| `name` | Its name. Ephemeral keys are named after their machine or API key. |
| `access_key_id` | `FLK` and 17 characters. Not secret. |
| `org` | The organization whose buckets it covers. |
| `read_only` | Whether it can only read. |
| `ephemeral` | Whether it was issued for a CLI sign-in (`session_id`) or an API key (`api_key_id`). |
| `source` | That sign-in's machine, or that API key's name. |
| `created_at`, `last_used_at` | When it was made, and last used (recorded at most once a minute). |
| `expires_at` | When the proxy stops taking it, or `null` for never. It is sooner than the key's own expiry when the organization has lowered its maximum since. |

| Endpoint | Who | Meaning |
|---|---|---|
| `GET /me/s3-keys` | anyone | Your keys that still work, as `{"keys": [...]}`, oldest first. |
| `POST /me/s3-keys` | browser sessions | Creates a long-lived key from `{"name": "notebook", "org": "acme", "read_only": false, "ttl": 604800}`. `ttl` is required: seconds, or `null` for never. `org` defaults to yours. A `ttl` longer than the organization's maximum (or `null` when it has one) answers 422. Answers 201 with the key, plus `secret_access_key`, `endpoint` and `region`, shown only now. API keys and CLI tokens get 403. |
| `DELETE /me/s3-keys/{id}` | anyone | Revokes one of your keys. Answers 204. The proxy refuses it from its next request. |

## Buckets[[buckets]]

A bucket is returned as:

```json
{"name": "checkpoints", "upstream_name": "00017-checkpoints", "created_at": 1793105538.1, "created_by": {"id": 3, "name": "Ana", "email": "ana@example.com", "avatar_url": null}}
```

`upstream_name` is its name on the S3 server. `created_by` is `null` once that account is deleted.

| Endpoint | Who | Meaning |
|---|---|---|
| `GET /orgs/{org}/buckets` | members | The organization's buckets by name, as `{"buckets": [...], "name_limit": 57}`. `name_limit` is the longest name this server takes. With `?deleting=true`, buckets deleted but still being emptied are listed too, with their `deleted_at`. |
| `POST /orgs/{org}/buckets` | members | Creates `{"name": "checkpoints"}`, on the S3 server too. Answers 201 with the bucket. An invalid name answers 422. A name in use, still being deleted, or already on the S3 server outside Flock answers 409. If the S3 server refuses, nothing is kept and the answer is 502. |
| `GET /orgs/{org}/buckets/{name}` | members | The bucket, with `events`: its history. |
| `DELETE /orgs/{org}/buckets/{name}` | org admins | Deletes the bucket and everything in it. Answers 204 once the name is free in the organization; the bucket is emptied and removed from the S3 server in the background. |

Each event is `{"kind", "user", "at", "detail"}`. `kind` is `created`, `deleted` or `purged` (removed from the S3 server). `detail.via` says how it was asked for:

| `via` | Meaning, with the other `detail` fields |
|---|---|
| `ui` | From the dashboard (a browser session). |
| `cli` | From the command line: `machine` is the CLI sign-in's hostname. |
| `api` | With an API key: `key_name` is its name. |
| `org` | Deleted with its organization. |
| `purge` | Removed by the background purge: `objects` is how many objects it held. |

## Key lifetimes[[lifetimes]]

Organizations carry `s3_ephemeral_ttl` and `s3_key_max_ttl`, in seconds, which org admins change with [`PATCH /orgs/{org}`](orgs#organizations). [Key lifetimes](../s3#key-lifetimes) explains them.

## Objects[[objects]]

The routes behind the dashboard's Storage tab. Any member can use them; they act on the S3 server with the global key. Objects' bytes don't go through them: `presign` signs URLs to the proxy for that.

| Endpoint | Meaning |
|---|---|
| `GET /orgs/{org}/buckets/{name}/objects` | One level of the bucket under `prefix` (default: the root), `limit` entries a page (1 to 1000, default 200), from `cursor`. Answers `{"prefix", "folders", "objects", "cursor"}`: `folders` are the keys up to the next `/`, `objects` are `{key, size, last_modified, etag}`, and `cursor` is the next page's, or `null` on the last. A folder's own marker (the key `prefix` itself) isn't listed. |
| `GET /orgs/{org}/buckets/{name}/object?key=` | An object's details, from a HEAD: `{key, size, last_modified, etag, content_type, metadata}`, `metadata` being its `x-amz-meta-*` headers without the prefix. 404 if there's no such object. |
| `POST /orgs/{org}/buckets/{name}/objects/delete` | Deletes `{"keys": [...], "prefixes": [...]}`: the objects, and everything under each prefix (ending in `/`). Answers `{"deleted": n}`, the number of keys asked to go. More than 10,000 in all answers 409 before anything is deleted, with `limit` and the `command` to use instead (`aws s3 rm --recursive`). |
| `POST /orgs/{org}/buckets/{name}/folders` | Creates the empty object `{"prefix": "runs/v1/"}` (ending in `/`), which makes the folder show up in listings. Answers 201. |
| `POST /orgs/{org}/buckets/{name}/presign` | Presigned URLs to the proxy, below. |

### Presigned URLs[[presign]]

`presign` signs URLs to the proxy (`FLOCK_S3_PUBLIC_URL`) with the caller's **browser key**: an ephemeral key of the request's sign-in (or API key) and the organization, named `browser (ephemeral)`. The newest one is reused while it has more than 15 minutes left (or the URL's lifetime, if longer), so most calls make no key. It's deleted with the sign-in, as other ephemeral keys are. A URL never outlives its key: with an ephemeral lifetime under an hour, URLs last less than asked.

The body names a `method` and the object's `key`:

| `method` | Other fields | Answer |
|---|---|---|
| `get` | `disposition`: `attachment` (default) or `inline`; `link`: `true` for a URL lasting an hour instead of 15 minutes; `content_type`, for `inline` only: an image, PDF, video, audio or `text/plain` type to serve it as | `{"url", "expires_at"}`. The URL sets `response-content-disposition`, with the key's last part as the file name. |
| `put` | `size`, which can't be over 100 MiB | `{"url", "expires_at"}`, a PUT of the whole object |
| `multipart` | `size` (up to 50 GiB), `content_type` | Starts a multipart upload: `{"upload_id", "part_size", "part_count"}`, parts being 16 MiB |
| `parts` | `upload_id`, `parts`: up to 100 part numbers | `{"parts": {"1": url, ...}, "expires_at"}`, a PUT URL for each |
| `complete` | `upload_id` | `{"url", "expires_at"}`, the POST of CompleteMultipartUpload |
| `abort` | `upload_id` | `{}`, once the upload is aborted |

The browser reads each part's `ETag` from the proxy's answer and sends them with the completion. The proxy answers CORS for the dashboard's origin (`FLOCK_WEB_URL`) only: preflights from it are answered without a signature, and `ETag` is among the headers scripts can read.
